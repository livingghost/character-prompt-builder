# Grounded World State and Scoped Realization

For one moment outside a planned unit, use [Story Context](story-context.md). It
selects the same base, ledger and process records at an explicit coordinate and
can feed its bounded view into a production task. Keep the unit plan for a
sequence of openings, closings and continuity links.

## Activation and ownership

Use this route when a portrayal depends on earlier or later conditions,
recurring subjects, shared world facts, information access, state-dependent
references, or a correction that could propagate through other outputs. It
covers words, still images, sound, performance and sequences. It leaves open
protagonist count, personified subject, genre, theme, conflict, climax, linear
presentation, growth arc, film pipeline and the inventory of emotional states.

Start from the requested artifact. A timeless design can skip chronology and a
state plan, and a conversation can use this reasoning before any file exists.
Persistent, explicitly ordered state work uses the plan and tool below.

This route coordinates four owners and leaves the world ledger, persona,
adoption system and generation package in their own roles:

- The [creative method](narrative-development.md) owns the work's scope and interfaces.
- [Authorial Intent](authorial-intent.md) owns creator aims.
- [Character Performance](character-performance.md) applies individualized identity and expressive rules.
- The [State Event Ledger](../state-event-ledger.md) is the sole deterministic event/process authority.

The design borrows explicit world/state addressing, separation of planned state
from rendering, and diagnose-correct-select from FilmWorld. Provenance
safeguards and director intent are future directions in that paper, not
reproduced capabilities. This CPB route adds generic authoring, information
boundaries and intent-aware review; the precise
[source and adaptation boundary](../research/filmworld-design-notes.md) governs
attribution.

## 1. Establish scope and evidence before making state authoritative

Read the actual source span and adopted design rather than generated summaries
alone. Resolve aliases only when they demonstrably refer to the same subject in
the declared continuity; identical names can denote different subjects, and
different names can denote one. Unresolved identification stays unresolved
rather than taking one convenient identity.

Keep source-explicit content, an inference, a creator's design decision and an
observation of an output apart. Record the actual source and locator,
uncertainty, adopted scope and affected fields. A plausible completion of an
underspecified source is a proposal rather than a recovered fact, and a
consistent sequence propagates a mistaken first interpretation just as
consistently.

Base state needs a basis as well as events: for a consequential field, retain
its owning record, source locator or design decision and actual adoption. In a
structured plan the base provenance binds exact entity/field pointers to
evidence, while approved event and process evidence lives in its own records,
not in a second plan-side editable ledger. A hash identifies inspected bytes;
the source's meaning, semantic applicability, adoption, image identity and the
creator's consent need evidence beyond a hash or the word approved.

Keep actual conditions, testimony, belief, uncertain inference, narration,
audience disclosure and creator-only planning distinct. An unknown stays
unknown, a missing value missing and an occluded part occluded; a confidence
threshold leaves a hypothesis a hypothesis. Purposeful ambiguity needs a scoped
design basis; an unexamined field is still a gap.

## 2. Separate the addresses that serve different jobs

| Address or owner | What it means | What it does not authorize |
|---|---|---|
| Subject/entity identity | Which recurring referent this is, within its continuity | A particular expression, role, costume or pose |
| Persona/world identity profile | What maintains recognizable identity, including designed change | Knowledge of every future event |
| State snapshot | Established conditions at an explicit target order and scene context | An artistic choice or proof that a generated output matches |
| Role-specific reference key | This entity's explicitly chosen relevant facets for one use | Whole-person identity, canon adoption, model compatibility or a general quality score |
| Asset hash/binding | Exact bytes, adopted scope and bounded influence of a reference | All visible source-state details as permanent identity |
| Authorial intent | What the creator chooses to sustain, contrast, reveal or disrupt | A quiet rewrite of world rules or historical facts |

Select reference facets by purpose. A clothing change can leave a voice
reference in place and an emotional change can leave an identity reference in
place, while a meaningful new form can require different visual evidence.
Include only declared expression channels; a universal identity/age/costume
tuple, a mandatory human face encoder and species-derived anatomy are outside
the design.

Reference keys are queries for review, not evidence of perceptual equivalence. Two equal keys mean only that the authored facet selections match
under the same entity, timeline and role; a wrong selection can omit a
load-bearing distinction, so review it. Two distinct keys leave open whether one
asset suits two separately scoped uses.

A first generated appearance remains a candidate; reuse only adopted, applicable
evidence. When transporting image references, the canonical Reference Selection
and Reference Use Plan still own state eligibility, influence, exclusions and
precedence. This plan leaves asset lists and model adapters to those owners; a
visual-ID embedding and automatic identity transfer between generation backends
are outside its scope.

## 3. Distinguish occurrence, telling and execution

Plan only the relevant portion of the world's state trajectory before realizing
it; one image can be drawn before the complete work is finished. Recompute
requested states from the authoritative base and events/processes, not the last
generated picture or the last scene in presentation order; a candidate's render
defects stay out of the next state's input.

Record story order within each explicitly chosen timeline, and presentation
order separately. A flashback can appear after a future scene while keeping its
own knowledge, damage and wardrobe; parallel scenes, revisits, ellipses, repeated
accounts and editorial reorderings need their own relations. Give an alternative
its own reviewed continuity/base rather than merging incompatible worlds. Naming
timelines is record-keeping; a native branching-story execution engine is a
separate, unclaimed capability.

The resolver's integer story orders are event positions rather than physical
durations: leave elapsed time unestimated, keep a partial order partial, and
keep a cycle out of any serialized chronology. Where that model is inapplicable,
retain the design in prose and state the serializer boundary. A unit can depict
a reverse interval; label its intended temporal treatment in the design and use
explicit boundary comparisons instead of an inferred forward chain.

For a continuous connection, record the outgoing and incoming states and the
specific dimensions that must match; a pose can change across an edit and other
fields can differ. An ellipsis can preserve injury while changing place, and a
match cut can connect imagery while physical time stays disconnected. Only
declared comparisons are machine checked.

Processes use the existing authored milestones and lifecycle rules.
Natural-language descriptions can retain subtle, continuous or mixed feelings;
interpolation of numerical or emotional states is outside the resolver, and a
missing intermediate milestone leaves psychological or physical continuity an
open question. Author a supported projection at the precision the output needs.

## 4. Resolve a unit's expressive contract

For each consequential unit, identify the applicable world conditions,
information access, persona phase and authorial intent. Define what is retained,
changed, revealed, withheld or deliberately broken, and the authorized reason; a
unit can stay unchanged.

A stable posture through distress and a switch from playful to assured delivery
are different portrayal designs that can share one state label. Read the
identity profile and contextual rules, then select words, voice, facial
expression, movement, timing and omissions. Persist adopted aftermath across
line and scene boundaries. A simulated example leaves open whether its event
happened. [Portrayal Principles](../portrayal-principles.md) can help design a
rule; ready-made canon and the complete persona come from their own owners.

Keep creator intent, expected world state and expected realization distinct. For
adaptation, use the adopted fidelity policy. Omission, rearrangement, symbolism
and reinterpretation can be legitimate choices, and a creator aim leaves an
accidental deviation accidental. Resolve their scope and status before using
them as a correction criterion.

## 5. Pass only the information the consumer should receive

Create an explicit consumer view (one recipient's slice) for each recipient and
purpose. Select individual state leaves and author-reviewed local
instructions; the full persona, hidden design register, raw source file, future
state, evidence narrative and diagnostic history stay out of any automatic copy.
A label such as author-only leaves content in place, so inspect the actual
exported body.

The renderer may need visible conditions unknown to the character. A performer
may need an outcome while their character stays unaware of it. The audience may
receive less than either. Make these decisions explicitly; a role name gives a
script too little to infer appropriate knowledge from. Manually written view
instructions can themselves disclose a secret and must be reviewed.

A single-image view selects one depicted moment rather than a contradictory
opening and closing pose. Words and time-based media can express transitions
where their form permits. Scene/plot readers, prompt retrieval, approved
production specs, reference preparation and generation verification remain
required on their respective activated paths. A consumer view is only the
recipient's slice; a model request, execution permission and a sealed Generation
Package each come from their own step.

## 6. Inspect, correct and choose without changing canon by accident

Use [the realization review form](../../templates/realization/review-template.md) and
[State Write-back and Drift Routing](../state-writeback-routing.md). The routing
document owns diagnosis by owning layer, the smallest justified repair, candidate
comparison under one contract and the task-appropriate retry budget. Compare the
exact inspected output and locator against the intended conditions, relevant
reference evidence and portrayal intent over the inspected span. Look at the
image, read the prose or listen to the sound; a passing structural check covers
structure only. Judge against the adopted intention, purposeful ambiguity and
stylization included, rather than a numerical artistic score or generic
naturalness.

Only an explicit adoption decision changes canonical facts. Changes to sources
or intent require an impact review and fresh compilation of dependent views:
recompile a stale view rather than relabeling it, and reseal a source hash only
as a visible, reviewed step.

## Local realization plan and CLI

The [plan schema](../../schemas/authoring/world-realization-plan.schema.json) and
[empty starter](../../templates/realization/world-realization-plan.json) describe
a local coordination file, not a new shared-state interchange contract.
Plans reference the existing base, `state-event` JSONL and `state-process` array
by source ID; every source path is a literal project-relative path with the
SHA-256 of the complete file bytes, and events remain the canonical mutation
records.

Use [the worked unpeopled example](../../examples/world-realization/README.md) as
a runnable structural example, not adopted world lore. From the installed
`SKILL.md` directory:

```bash
python scripts/world_realization.py inspect --root <project> --plan plan.json
python scripts/world_realization.py build --root <project> --plan plan.json --out <new-output-directory>
python scripts/world_realization.py verify --root <project> --plan plan.json --bundle <output-directory>
python scripts/world_realization.py impact --root <project> --plan plan.json
python scripts/world_realization.py --help
python scripts/world_realization_smoke_test.py
```

- `inspect` returns the full author-facing result and writes nothing.
- `build` stages a new directory and publishes it only after all explicit
  comparisons pass; existing outputs stay untouched.
- `verify` recompiles from currently pinned sources and checks all output bytes
  and the exact file inventory.
- `impact` reports stale or missing sources and conservatively affected
  units/views; hashes, approvals and the ledger stay as they were. A changed
  event/evidence source affects every unit on that timeline, and that breadth
  is deliberate rather than a minimal semantic invalidation.

Plan fields:

- `sources`: unique IDs, local paths and exact hashes; world, persona, intent and
  evidence can be separate sources whose status and authoritative meaning remain
  in their owning records.
- `timelines`: explicit base/events/processes source IDs and `base_provenance`.
  The base has the five existing buckets: characters, relationships, environments
  and props are entity-ID maps, and `world` stays the existing aggregate object
  rather than an entity map.
- `base_provenance`: existing entity/field pointers, each with evidence. Every
  scalar base leaf must be covered by that exact pointer or an explicit ancestor;
  scope coverage is checked, source meaning is left to the author, and an empty
  map stays empty.
- `evidence`: each participating event/process evidence record and base binding
  names `source_id`, a nonblank `locator` and `basis` (`source-explicit`,
  `author-decision`, `inference`, `observation`). All IDs resolve to pinned
  files.
- `units`: array order is presentation order. Each unit independently selects
  its timeline, scene context, opening and closing story orders/times, source
  dependencies and exact intent IDs; `medium` is free text, not a filter for a
  small set of genres or formats.
- `reference_queries`: an entity pointer (or aggregate `/world`), role and exact
  scalar facet pointers, each of which must exist. The key hashes those fields,
  values, entity and timeline only; unrelated states, camera settings,
  presentation position and a snapshot's administrative ID stay outside it, and
  section 2 says what a key proves. The output is a lookup key; adopting an asset and
  producing a model-facing embedding are separate decisions.
- `views`: individually named recipients, purposes, scalar `state_fields`,
  reference-query IDs and deliberately authored `instructions`. Containers are
  rejected to prevent accidental subtree export. Missing fields produce
  `present: false` and omit the value; explicit null stays present.
- `links`: named endpoints, a free-text relation, basis and explicit scalar
  `equal`/`different` assertions. Both operands must exist; two missing fields
  count as unproven rather than equal. `continuous` requires one timeline and
  nondecreasing boundary orders; other authored relations carry only the tests
  the author requests, and array adjacency alone yields none.

Output contains `world-realization-bundle.json`, canonical world snapshots under
`snapshots/` and separate consumer files under `consumer/`; only the consumer
files go to a recipient. The bundle holds the source inventory, evidence
locators, applicable intent statuses, reference facets, explicit comparisons and
review notes; it is author-facing and can contain hidden or future information.
Exact hashed bytes bind the build and, as section 1 says, prove bytes only.

Nonexistent files, stale hashes, malformed data, duplicate IDs, bad intent
links, unsafe paths, missing evidence, invalid temporal inputs and failed
explicit comparisons block publication. An unadopted intent link is reported as
a review note and left as it is. An empty plan can pass structure while
remaining an unpopulated draft. Exit 0 means the requested structural operation
succeeded, exit 1 reports errors or changed dependencies, and invalid CLI use
returns 2.

No network or model call occurs. Paths must stay within the declared root;
remote/absolute paths, parent traversal and symlinks are rejected. Source counts,
text length and compiled data have no implicit byte or item ceiling; parsing and
compilation need enough host memory and storage, and an operational failure is
not a successful partial realization. Split a large requested scope into
explicitly dependent plans rather than silently truncating it. These are
implementation bounds, not constraints on a work's length or number of subjects.


## Artifact evidence and completion

For a saved deliverable, continue through [Production Execution](production-execution.md), preserving this document's interpretation, retrieval, approval and adoption boundaries. Prepare the exact inputs, capture the real output, bind review and selection to it, then complete and close the work task. `scripts/production_workflow.py status`, `impact` and `resume` recheck dependencies and artifact bytes. A progress checkbox, a search hit or a newly created image is not production completion or canonical adoption.
