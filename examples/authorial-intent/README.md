# Authorial intent: worked structural example

Read [Authorial Intent](../../references/runtime/authorial-intent.md) and
[Character Performance](../../references/runtime/character-performance.md) for the production
procedure. These independent hypothetical designs illustrate scoped records, not preferred genres,
cast counts or approved character proposals. The notes are realization probes, not full personas.

The [design register](design/teaching.md) owns three proposed intents. The
[unpeopled observation](notes/landscape.md), [stable-presence probe](notes/steady.md) and
[designed-switch probe](notes/switch.md) reference them. These are separate possible applications;
no two-character relationship or required ensemble is implied. Local conditions and subject
identity still need their actual owners in a real project.

From the installed skill root:

```bash
python scripts/authorial_intent_audit.py --root examples/authorial-intent notes/landscape.md notes/steady.md notes/switch.md --fail-on-gaps
```

A successful report establishes these current records' structure, exact references and hashes.
It explicitly does not adopt the intentions, select applicability, infer emotion or rate prose.
The proposed statuses cause review notes, not fabricated approval. Only explicit reference
closure is read; the tool is not a whole-project knowledge or consumer-view exporter.

For a real handoff, supply a scoped view of the relevant adopted instruction and current facts.
Do not pass unrelated or concealed author entries to a limited-viewpoint consumer. Use a review
of the actual output span to assess the intent, and record any proposed departure at its real time
of discovery instead of claiming it was always planned.
