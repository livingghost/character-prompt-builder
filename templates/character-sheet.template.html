REUSABLE JSON EDITOR - NOT A PER-CHARACTER HTML DOCUMENT

Use this page when a recurring character is first defined or when its stable canon is revised. Do not edit the HTML source for each character. Enter data in the page and save it by exporting sheet-data.json.

  1. For a new character, start blank. For an existing character, import its sheet-data.json before editing.
  2. Enter stable identity facts only. Do not put the current scene, camera, one-off pose, lighting, damage, dirt, or other transient state here.
  3. Export sheet-data.json into one folder dedicated to that character. Browser edits are not saved anywhere until export.
  4. Run the renderer on that folder. The renderer reads JSON plus a layout profile and creates the renderer-owned PNG composition base, edit mask, layout, and exact panel-only requests. It does not screenshot or rasterize this HTML page.
  5. For a maskless model, send only each declared panel prompt and its accepted identity references, then compose the artwork-only result files into the renderer-owned base. Never send the full sheet as a reference image and call that a masked edit. A full-sheet request is allowed only for an interface that actually applies the pixel edit mask.
  6. Harvest the returned sheet as candidates, explicitly accept only approved panel crops, and render the accepted panels as a later identity reference board.
python scripts/render_character_sheet.py <character-sheet-folder> --mode scaffold --out <character-sheet-folder>/model-fill

Do not reopen or rewrite this editor for every new image. Reopen it only when the character canon, the requested sheet panels, or an accepted reference artifact changes. Pose and scene instructions belong in the current generation prompt.

Panel-set scope: the renderer profile named in field.sheet_layout_profile is authoritative; blank uses the domain-neutral general profile. Panel letters are profile-local and are intentionally replaced by stable slot ids in this editor. Imported and profile-resolved slots receive controls automatically. Bundled profile panels are starters, never a closed list or a maximum; undeclared anatomy is never generated.

Model-fill brief

These fields define what the image model must draw before any accepted reference exists. Separate the unobstructed base form from the dressed, covered, shelled, or equipped form so both can be compared direction by direction.
Describe the stable visible design: silhouette, anatomy, face, materials, markings, palette behavior, and signature items. Do not describe the current scene.
Rendering treatment for the sheet itself. Later scene prompts remain authoritative for pose, expression, camera, environment, and lighting.
State exactly what every profile-declared unobstructed view must show when removable clothing, coverings, equipment, and carried items are absent. For a person or anthro this can be the unclothed body; for a machine, construct, swarm, or other entity it is the underlying chassis, topology, or canonical configuration. Declare body covering, component count, connection pattern, sex features when relevant, and anything that must not be invented.
Describe the primary visible state applied over the same base form: silhouette, layer order, fastenings, openings, footwear, tail or appendage accommodation, shells, modules, and fixed carried equipment. Leave blank only when no distinct dressed, covered, shelled, or equipped state exists.
Name and Species / Domain establish selectable identity. Blank text is unresolved; a dash means not applicable. Image generation is controlled separately by each panel's Model-fill policy: Auto uses declared sheet data, Generate forces a new candidate, Keep protects an accepted image, and Skip excludes the panel.
Binding metadata (authoritative identity scope)

The binding value is forwarded to image generation and reference-board selection. Fixed facts are preserved at their declared scope; variable facts remain variable and are excluded from the identity-only board.

  • kind-fixed - inherited from the referenced kind
  • character-fixed - shared across this character's forms
  • individual-fixed - fixed on this individual or form sheet
  • variable - allowed to vary only under the written rule

Signature marks - the fixed identity

When declared, landmark-anchored marks may include tattoos, scars, birthmarks or mole patterns, heterochromia, named pattern events, notches, or chipped plates. For every mark, declare its side in Laterality. If it is unilateral or otherwise asymmetric, Counterpart rule must also state what the corresponding opposite side has instead, including explicitly “no mark”, “intact”, or the different feature. For a fixed mark, Visibility / occlusion rule states every orientation or panel condition where the anchor must show the same mark and the only conditions that may hide it. This provides positive and negative visual evidence and prevents accidental mirroring or intermittent disappearance.
